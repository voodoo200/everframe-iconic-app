# EVERFRAME ICONIC CRM v0.2 — настройка

## Что готово
Рабочая авторизация email/пароль через Supabase Auth, общая PostgreSQL-база, изоляция по рабочей группе через RLS, синхронизация при повторном открытии/обновлении, создание/редактирование/удаление контактов, фильтры и напоминания. Интерфейс v0.1 сохранён.

## Запуск (владелец проекта)
1. Создайте новый проект на https://supabase.com/dashboard . Используйте надёжный пароль базы.
2. В SQL Editor выполните `schema.sql`.
3. В Authentication > Users создайте двух пользователей (Елена и помощник) с индивидуальными адресами и паролями; убедитесь, что email подтверждены. Не публикуйте пароли.
4. В SQL Editor выполните:

```sql
insert into public.workspaces(name) values ('THE ICONIC') returning id;
```

Скопируйте UUID созданного workspace. Из Authentication > Users скопируйте UUID двух пользователей. Выполните, заменив три UUID:

```sql
insert into public.workspace_members(workspace_id,user_id,role) values
 ('WORKSPACE_UUID','ELENA_USER_UUID','owner'),
 ('WORKSPACE_UUID','ASSISTANT_USER_UUID','assistant');
```

5. В Supabase Project Settings > API Keys скопируйте **publishable/anon** ключ (НЕ `service_role`, НЕ secret key) и Project URL. Вставьте в `config.js`. Публичный ключ допустим в браузере ТОЛЬКО с включённой RLS.
6. Опубликуйте файлы `index.html`, `cloud.js`, `config.js` вместе на **отдельном приватном по смыслу URL** (например /crm/ в GitHub Pages); доступ к данным защищает Supabase Auth/RLS, а не секретность адреса. Не заменяйте существующую анкету `index.html` в корне сайта.
7. Войдите под обеими учётными записями, создайте тестовый контакт, проверьте синхронизацию после обновления на другом устройстве.

## Ограничения
- Пока нет автоматического поиска, Telegram-уведомлений, автоматических напоминаний, загрузки файлов, истории действий по отдельным событиям и реального времени без обновления.
- CSV экспортирует текущую загруженную выборку (до 1000 контактов). Импорт JSON в серверную базу отключён.
- Синхронизация происходит после сохранения и при обновлении страницы, не мгновенно между двумя открытыми вкладками.
- Серверная уникальность контактов/ссылок действует внутри workspace.
- Не включайте публичную регистрацию для CRM. Выдавайте доступ через администраторскую панель.
- Не вставляйте service_role ключ в HTML/JS/GitHub.
- Данные кандидатов — персональные данные. Перед реальной работой проверьте правовые основания обработки, политику хранения и применимое законодательство по географии пользователей и субъектов данных.
- Для коммерческого использования нужно добавить аудит изменений, резервное копирование, восстановление, управление доступом и антиспам для публичной анкеты.
